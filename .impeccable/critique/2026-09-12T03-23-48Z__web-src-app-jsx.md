## Priority Issues

**[P0] The carousel duplicates register rows 1–5 in place**
- Why: five carousel names = the first five register names, one row before the strip. A person printed twice within 60px reads as a data error about that person. Costs 5 of the first 11 tab stops between result 1 and result 2. Round 3 moved the strip after the first group but drew it from the same pool, so it overlaps whenever the newest day has one or two names.
- Fix: drop it from the register (the mini widget already puts a face in the article; it does not render on phones), or source it from records the register is not showing and place it after the last visible group.
- Command: /impeccable distill

**[P0] The row's summary repeats the row**
- Why: "jensen" returns two Jensens and nothing distinguishes them. ~1,500px per page of echo, pushing `.entry__home` (the one differentiator) down.
- Fix: strip the template first clause, render the tail or the excerpt, drop the line when empty; move age into the fact line.
- Command: /impeccable distill

**[P1] A misremembered spelling is a silent dead end**
- Why: "Jenson" returns one stranger, never offers Jensen. A zero-result state triggers the good empty state; a one-wrong-result state does not.
- Fix: a "Close spellings" tier below mentions when names < 3, edit distance ≤ 1 on the surname, surfaced in the count line.
- Command: /impeccable harden

**[P1] The town the placeholder invites returns zero names**
- Why: the field says "Name, town or funeral home"; "wausau" answers "0 names · 362 more mentions" on the newsroom's own town. The town facet exists with counts; search never reaches it.
- Fix: a towns bucket mirroring `homes`, same line grammar, wired to the town filter; count it in the search line.
- Command: /impeccable clarify

**[P2] Three measured accessibility failures**
- Why: on row hover/focus `.entry__span` and `.entry__home` measure 4.44:1 (below AA) in the deciding state; every control but the search box has a 1.34:1 boundary on an identical background (WCAG 1.4.11); Pause shows "Play" while announcing "Resume auto-advance" (2.5.3), introduced in round 3.
- Fix: a `--muted-on-wash` token for text on the hover wash, a `--rule-control` border token for controls (hairline stays decorative), and a visible "Resume" label.
- Command: /impeccable audit

**[P3] The family's only submission path is an unaddressed mailto**
- Why: no "@" anywhere in the rendered page, though CLAUDE.md says the address is shown in the masthead. No mail handler means a silent failure at the moment the empty state sent the family here. Seven fields, one required, including age (derivable) and no submitter identity.
- Fix: render the address and the phone as a visible fallback under the actions; cut age and source_date; add "Your name and phone" as required.
- Command: /impeccable harden
